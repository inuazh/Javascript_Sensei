# Контент уроков

Весь учебный контент лежит в этой папке. Чтобы добавить или поменять уроки, код приложения трогать не нужно.

| Файл               | Что в нём                                    |
| ------------------ | -------------------------------------------- |
| `sections.json`    | Разделы и их темы: порядок, иконки, цвета    |
| `<sectionId>.json` | Уроки одного раздела                         |
| `index.ts`         | Реестр файлов с уроками, по строке на раздел |

Формат описан zod-схемой в `src/content/schema.ts`: из неё получаются и TS-типы приложения, и проверки валидатора. Если этот документ и схема расходятся, права схема.

## Как добавить раздел

1. Создай `content/<sectionId>.json` с уроками.
2. Добавь раздел с темами в `sections.json`. `id` тем уникальны во всех разделах.
3. Добавь одну строку в `SECTION_FILES` в `index.ts`:
   ```ts
   async: () => require('./async.json'),
   ```
4. Запусти `npm run validate:content` и `npx prettier --write content`.

Главный экран, экран темы, прогресс, тренировка и достижения подхватят раздел сами.

## Урок

```json
{
  "id": "promise-01",
  "topicId": "promise",
  "title": "Что такое Promise",
  "order": 0,
  "theory": { "blocks": [] },
  "questions": []
}
```

- В теме 5 уроков, в уроке 5–6 вопросов.
- `id` уроков и вопросов уникальны глобально: `<topicId>-NN` и `<topicId>-NN-qN`. **Не меняй и не удаляй `id` опубликованных уроков и вопросов**: к ним привязаны прогресс пользователей и интервальные повторения.
- Уроки темы идут от простого к сложному, последний урок темы — закрепление.

## Теория

Короткая карточка перед вопросами, на 20–40 секунд чтения. Она объясняет ровно то, что проверяют вопросы урока. Примеры — уроки `variables-01` и `variables-02` в `basics.json`.

```json
"theory": {
  "blocks": [
    { "type": "text", "text": "**Переменная** — это имя для значения. Пишем через `let` или `const`." },
    { "type": "code", "code": "let score = 10;\nconsole.log(score); // 10", "caption": "необязательная подпись" },
    { "type": "tip", "text": "Совет или хорошая практика." },
    { "type": "warning", "text": "Частая ловушка." }
  ]
}
```

- В `text`, `tip` и `warning` работают `` `код` `` и `**жирный**`.
- 3–6 блоков, хотя бы один `code`. Вывод показывай комментарием `// результат`.
- Пиши на «ты», коротко и по делу, без вступлений вроде «в этом уроке мы узнаем».

## Вопросы

У каждого вопроса есть `id`, `type` и `explanation`. `title` необязателен: по умолчанию подставляется заголовок по типу («Что выведет код?» и т. д.). `explanation` показывается после ответа: объясни **почему**, а не повторяй ответ.

Для вопросов с вариантами (`output`, `trueFalse`, `fill`): `options` — варианты, `correct` — индекс правильного (с нуля). Приложение **перемешивает варианты** при каждом показе, поэтому порядок в JSON не важен, а в объяснениях нельзя ссылаться на «вариант B» или «первый вариант». Можно добавить `optionExplanations` — массив той же длины с пояснением к каждому неверному варианту (для правильного — `null`). Пояснение показывается, когда пользователь выбрал этот вариант. Пиши их для типичных заблуждений.

**`output`: что выведет код.** Валидатор выполняет `code` и сверяет вывод с отмеченным вариантом.

```json
{
  "id": "data-types-01-q1",
  "type": "output",
  "code": "console.log(typeof null);",
  "options": ["null", "object", "undefined", "Error"],
  "correct": 1,
  "optionExplanations": [
    "typeof никогда не возвращает \"null\"",
    null,
    "undefined — значение переменной без значения",
    "Код корректен"
  ],
  "explanation": "Историческая ошибка языка: typeof null возвращает \"object\"."
}
```

Как записывать ответы, чтобы проверка их распознала:

- несколько `console.log` пишутся через пробел: `"1 3 2"`;
- массивы: `[1, 2]`, строки внутри в кавычках: `["a", "b"]`; объекты: `{ a: 1 }`;
- если код падает, ответ — имя ошибки (`"ReferenceError"`, `"TypeError"`) или `"Error"`;
- если ничего не выводится — `"Ничего"`.

Таймеры, `Promise`, `async/await` и `queueMicrotask` поддерживаются, порядок вывода считается как в браузере. `setInterval`, `fetch` и DOM недоступны.

**`trueFalse`: два варианта.** `code` необязателен, `options` ровно из двух строк.

**`fill`: заполни пропуск.** Показывается `codeBefore` + пропуск + `codeAfter`. Правильный вариант должен быть **единственным** рабочим: если код работает и с другим вариантом, замени этот вариант.

**`order`: расставь строки.** `lines` в правильном порядке, `shuffled` — порядок показа (перестановка индексов `lines`, не совпадающая с правильным). Строки не повторяются, правильный порядок единственный. Если строки — не код, а шаги словами (трассировка, рейтинг), поставь `"steps": true`: тогда кнопка «Запустить» не показывается, а валидатор не требует, чтобы строки собирались в код.

**`findBug`: найди баг.** Короткий код на 3–10 строк, пользователь нажимает на строку с ошибкой. `bugLine` — номер этой строки, **считая с 1**. `fixed` необязателен: исправленный код, его покажут после неверного ответа (без `fixed` покажут «Строка N»).

```json
{
  "id": "objects-05-q6",
  "type": "findBug",
  "code": "const defaults = { size: 14 };\nconst settings = defaults;\nsettings.size = 18;\nconsole.log(defaults.size); // ждём 14",
  "bugLine": 2,
  "fixed": "const defaults = { size: 14 };\nconst settings = { ...defaults };\nsettings.size = 18;\nconsole.log(defaults.size); // 14",
  "explanation": "`settings = defaults` копирует ссылку, а не объект, поэтому меняется и defaults."
}
```

- Баг должен быть **в одной строке**, и только в ней. Пустую строку отметить нельзя.
- Покажи, что код должен делать: комментарием с ожидаемым выводом (`// ждём 14`) или в `title`.
- Бери настоящие частые ошибки, а не опечатки. Если есть `fixed`, валидатор запускает оба варианта и предупреждает, если они выводят одно и то же: баг обязан менять поведение.

## Проверка

`npm run validate:content` проверяет схему, связи между файлами, уникальность `id`, корректность `correct`, `shuffled` и `bugLine`, **выполняет код каждого `output`-вопроса** и сравнивает вывод `code` и `fixed` у `findBug`. Запускается в CI на каждый PR.

Валидатор не проверяет смысл: правильность теории и объяснений, вопросы `trueFalse` и `fill`. Их нужно вычитывать, лучше всего запустив код из вопроса руками.

Проверить код только одного раздела: `npm run validate:content -- async`.
