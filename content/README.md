# Контент уроков

Весь учебный контент лежит в этой папке. Чтобы добавить или поменять уроки, код приложения трогать не нужно.

| Файл | Что в нём |
|---|---|
| `sections.json` | Разделы и их темы: порядок, иконки, цвета |
| `<sectionId>.json` | Уроки одного раздела |
| `index.ts` | Реестр файлов с уроками, по строке на раздел |

## Как добавить раздел

1. Создай `content/<sectionId>.json` с уроками (формат ниже).
2. Добавь раздел с темами в `sections.json`. `id` тем должны быть уникальны во всех разделах.
3. Добавь одну строку в `SECTION_FILES` в `index.ts`:
   ```ts
   async: () => require('./async.json'),
   ```
4. Запусти проверку:
   ```bash
   npm run validate:content
   ```

Всё остальное (главный экран, экран урока, прогресс в профиле, ежедневный челлендж) подхватит новый раздел само.
Если у раздела нет своего цвета в `SectionColors` (`src/constants/theme.ts`), берётся `color` из `sections.json`.

## Формат урока

```json
{
  "lessons": [
    {
      "id": "promise-01",
      "topicId": "promise",
      "title": "Что такое Promise",
      "order": 0,
      "questions": [ ... ]
    }
  ]
}
```

В каждой теме обычно 5 уроков, в каждом уроке 5 вопросов. `id` уроков и вопросов уникальны глобально: `<topicId>-NN` и `<topicId>-NN-qN`.

## Типы вопросов

`correct` — индекс правильного варианта в `options`, счёт с нуля. У каждого вопроса есть `title` и `explanation`.

**`output`: что выведет код.** Валидатор выполняет `code` и сверяет вывод с отмеченным вариантом.
```json
{ "type": "output", "title": "Что выведет код?",
  "code": "console.log(typeof null);",
  "options": ["null", "object", "undefined", "Error"], "correct": 1,
  "explanation": "..." }
```
Как записывать ответы, чтобы проверка их распознала:
- несколько `console.log` пишутся через пробел: `"1 3 2"`;
- массивы пишутся как `[1, 2]`, строки внутри массивов в кавычках: `["a", "b"]`;
- объекты пишутся как `{ a: 1 }`;
- если код падает, ответ — имя ошибки (`"ReferenceError"`, `"TypeError"`) или просто `"Error"`;
- если код ничего не выводит, ответ — `"Ничего"`.

Таймеры, `Promise`, `async/await` и `queueMicrotask` поддерживаются: порядок вывода считается так же, как в браузере. `setInterval`, `fetch` и DOM недоступны.

**`trueFalse`: два варианта.** `code` необязателен, `options` всегда из двух строк.

**`fill`: заполни пропуск.** На экране показывается `codeBefore` + пропуск + `codeAfter`. Варианты в `options` должны различаться на вид, а правильный должен быть ровно один.

**`order`: расставь строки.** `lines` идут в правильном порядке, `shuffled` — порядок, в котором их увидит пользователь (перестановка индексов `lines`). Строки не должны повторяться: правильным засчитывается только один порядок.

## Что проверяет `npm run validate:content`

- `sections.json`, `index.ts` и файлы разделов согласованы между собой;
- `id` не повторяются, у каждой темы есть уроки, `order` не повторяется;
- `correct` указывает на существующий вариант, варианты не повторяются;
- `shuffled` — перестановка, которая не совпадает с правильным порядком;
- код из каждого `output`-вопроса действительно выводит отмеченный ответ.

Валидатор не проверяет правильность объяснений, вопросы `trueFalse` и `fill`. Их нужно вычитывать вручную.

Проверку одного раздела можно запустить так: `npm run validate:content -- async`. Эта же проверка запускается в CI на каждый PR, который меняет `content/`.
