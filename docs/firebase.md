# Firebase: защита рейтинга

Рейтинг хранится в Firebase Realtime Database. Без авторизации любой может отправить запрос и записать себе сколько угодно XP или перезаписать чужую запись. Защита из двух частей:

1. **Анонимная авторизация.** Приложение само создаёт анонимного пользователя (без регистрации и без данных), и его `uid` становится id игрока.
2. **Правила базы** (`database.rules.json`):
   - писать можно только в свою запись `leaderboard/{uid}`;
   - все поля проверяются по типу и диапазону, лишние поля запрещены;
   - новая запись — не больше 5000 XP, дальше XP может расти не быстрее ~600 XP в минуту (плюс запас 1000), `updatedAt` ставит сервер;
   - читать рейтинг можно всем.

Полностью накрутку на клиентском приложении исключить нельзя (XP считается на устройстве), но правила делают её медленной и не дают трогать чужие записи.

## Что нужно сделать (≈5 минут)

Порядок важен: сначала выпусти версию приложения с ключом, потом включай правила. Иначе старые версии перестанут попадать в рейтинг раньше, чем пользователи обновятся.

1. **Включи анонимный вход.** [Firebase Console](https://console.firebase.google.com/) → проект `javascript-sensei` → Build → Authentication → Sign-in method → Anonymous → Enable.
2. **Добавь Web API key в приложение.** Project settings (шестерёнка) → General → «Web API Key». Вставь его в `app.json` → `expo.extra.firebaseApiKey` (ключ не секретный: он только идентифицирует проект, защиту дают правила). Либо задай переменную `EXPO_PUBLIC_FIREBASE_API_KEY` в EAS.
3. Собери и выпусти приложение.
4. **Опубликуй правила.** Realtime Database → Rules → вставь содержимое `database.rules.json` → Publish. Или через CLI:
   ```bash
   npx firebase-tools deploy --only database
   ```

После этого старые записи (без ника, из первой версии приложения) в рейтинге не показываются; игроки появятся заново под своим ником после следующего урока.
