# Firebase: защита рейтинга

Рейтинг хранится в Firebase Realtime Database, приложение работает с ней через REST. Без авторизации любой может отправить запрос и записать себе сколько угодно XP или перезаписать чужую запись. Защита из двух частей:

1. **Анонимная авторизация.** Приложение само создаёт анонимного пользователя (без регистрации и без данных), и его `uid` становится id игрока. Она включается **только если при сборке задана переменная `EXPO_PUBLIC_FIREBASE_API_KEY`** (переменная окружения EAS, встраивается в приложение при сборке). Без неё приложение пишет в базу без авторизации, и опубликованные правила такие записи отклоняют: читать рейтинг можно, попасть в него нельзя.
2. **Правила базы** (`database.rules.json`).

## Данные

```
leaderboard/{uid}         = { nickname, xp, streak, updatedAt }
weekly/{week}/{uid}       = { nickname, xp, streak, weekXp, week, updatedAt }
```

- `week` — номер недели: число дней от 1970-01-01 до её понедельника (неделя с понедельника 2026-11-02 — `20759`). Правила не умеют разбирать дату из строки, а с числом могут считать. У каждой недели свой список, поэтому старые недели не вытесняют текущую.
- Уровень не хранится: приложение считает его по XP.
- Приложение пишет обе записи одним атомарным multi-path `PATCH`. Если за неделю нет XP, недельная запись удаляется.

## Что проверяют правила

- Писать и удалять можно только свои записи (`auth.uid === $uid`), лишние поля и приоритеты (`.priority`) запрещены, `updatedAt` ставит сервер.
- `xp` и `weekXp` — целые числа. Новая запись: `xp` не больше 100 000 (весь курс даёт больше 20 000), `weekXp` не больше 20 000; дальше значение может расти не быстрее ~600 в минуту с прошлой записи; разовый прирост до 1000 разрешён, только если с прошлой записи прошла минута (иначе цикл частых записей добавлял бы по 1000 за запрос). `weekXp > 0` и не больше `xp`.
- `week` — понедельник (`week % 7 == 4`), не раньше чем за 7 дней (+1 день на часовые пояса) до текущего времени сервера и не в будущем. Ключ `{week}` должен совпадать с полем `week`.
- `nickname`, `xp` и `streak` в недельной записи должны совпадать с общей записью.
- `streak` растёт не больше чем на 1 в день и никогда не длиннее, чем существует приложение (с 2026-04-01): стрик в сутках считается по часовому поясу устройства, которого правила не знают, поэтому +1 разрешён при каждой записи, и только этот потолок не даёт накрутить стрик частыми записями; ненулевой стрик только при `xp > 0`. Вывести стрик из XP нельзя: повтор урока без улучшения продлевает стрик и не даёт XP.
- Ник: 2–20 символов, латиница **или** кириллица (русский алфавит), цифры, `_`, `.`, `-` и пробелы внутри. Смешивать латиницу и кириллицу нельзя. Управляющие, невидимые и RTL-символы не проходят. Регулярное выражение совпадает с `NICKNAME_RE` в `src/domain/nickname.ts` (это проверяет тест). Зарезервированные ники (admin, moderator, JS Sensei…) приложение проверяет само, с учётом похожих букв.
- Читать можно только так, как читает приложение: `leaderboard` — `orderBy="xp"`, `weekly/{week}` — `orderBy="weekXp"`, оба с `limitToLast` не больше 200. Выгрузить базу целиком или прочитать чужую запись напрямую нельзя.

Полностью накрутку на клиентском приложении исключить нельзя (XP считается на устройстве), но правила делают её медленной и не дают трогать чужие записи.

Выход из рейтинга в настройках удаляет общую запись и недельные записи текущей и прошлой недели (best effort: без сети запись останется, приложение предложит написать нам).

## Что нужно сделать

Порядок важен: сначала выпусти версию приложения с ключом, потом публикуй правила. Иначе старые версии перестанут попадать в рейтинг раньше, чем пользователи обновятся. Старые версии пишут в старом формате, поэтому после публикации правил их записи отклоняются; читать рейтинг они продолжают.

1. **Включи анонимный вход.** [Firebase Console](https://console.firebase.google.com/) → проект `javascript-sensei` → Build → Authentication → (Get started) → Sign-in method → Anonymous → Enable → Save.
2. **Скопируй Web API key.** Project settings (шестерёнка) → General → «Web API Key». Ключ появляется после того, как включена Authentication. Он не секретный: только идентифицирует проект, защиту дают правила.
3. **Задай переменную в EAS.** В текущем eas-cli (`env:create` устарел и скрыт, вместо него `env:set`):
   ```bash
   eas env:set --name EXPO_PUBLIC_FIREBASE_API_KEY --value <Web API key> --environment production --visibility plaintext
   ```
   Для внутренних сборок (`preview`) добавь `--environment preview` (флаг можно повторить). В старых версиях eas-cli та же команда называется `eas env:create` с теми же флагами.
   Или через сайт: [expo.dev](https://expo.dev) → проект `js-sensei` → Environment variables → Add variable → имя `EXPO_PUBLIC_FIREBASE_API_KEY`, значение — ключ, видимость Plain text, окружение Production → Save.
   Профили `production` и `rustore` в `eas.json` берут переменные из окружения `production`, `preview` — из `preview`. В логе сборки EAS должна быть строка «Environment variables … loaded from the "production" environment on EAS: EXPO_PUBLIC_FIREBASE_API_KEY».
   Для локального запуска положи ключ в `.env.local` (он в `.gitignore`) или выполни `eas env:pull --environment production`.
4. **Собери и выпусти приложение** (`npm run build:android`, `npm run build:rustore`).
5. **Опубликуй правила.** Realtime Database → Rules → вставь содержимое `database.rules.json` → Publish. Или через CLI:
   ```bash
   npx firebase-tools deploy --only database
   ```

Веб-версия на GitHub Pages собирается без ключа: читать рейтинг она может, писать — нет.

После публикации правил старые записи (без ника, из первой версии приложения) в рейтинге не показываются; игроки появятся заново под своим ником после следующего урока. Недельные списки прошлых недель приложение не читает; при желании старые узлы `weekly/{week}` можно удалить в консоли.

## Проверка правил локально

Правила вместе с атаками на них (чужой uid, накрутка XP и стрика частыми записями, подмена недели, лишние поля, чужие удаления, чтение без лимита) проверяет `scripts/test-database-rules.mjs`: запусти эмулятор (нужна Java) `npx firebase-tools emulators:start --only database` и затем `node scripts/test-database-rules.mjs` (`SLOW=1` добавляет проверку минутного запаса). Вручную: Загрузить правила в любое пространство имён: `PUT http://localhost:9000/.settings/rules.json?ns=test` с заголовком `Authorization: Bearer owner` и содержимым `database.rules.json`. Дальше запросы идут на `http://localhost:9000/...json?ns=test`, а пользователь задаётся неподписанным JWT в `?auth=` (эмулятор подпись не проверяет, `uid` берётся из `sub`).
